先给结论：

- 你们“测 5–8 个就枯竭”，一半是事件样本和严格纪律的正常结果，一半是把“探索、形态选择、正式确认”挤在同一层造成的。
- 不应全面放松预算；应增加一层不产生正式结论的低成本筛选，并把二元门控升级为“连续调制优先、门控只用于结构性否决”。
- 应做“因子概念 × 少量标准形态”，但不能做无约束笛卡尔积。统计检验单位应是“因子概念族”，形态搜索属于该族内部的选择成本。

先说明信息边界：文艺复兴的内部研究管线基本不公开，千禧是多经理、多 Pod 体系，也不存在可验证的统一“公司因子流水线”。Two Sigma 公开确认的是数据准备、特征化、建模、独立预测汇总、风险/成本约束组合这一链条，但具体模型仍属商业机密。[Two Sigma 官方研究流程](https://www.twosigma.com/about-us/)

## 问题 1：机构怎么挖掘和拆解因子？

### 1. 因子库不是“公式库”，而是“概念—实现—证据”三层库

建议 AlphaHive 建立如下层级：

```text
factor_concept
  └─ raw_definition
      └─ transform_family
          └─ fitted_variant
              └─ experiment / evidence / live vintage
```

例如放量因子：

```text
概念：washout 时是否出现异常参与/吸收
原始量：event_volume / trailing_baseline_volume
标准形态：
  1. robust percentile
  2. log-ratio + winsorized z
  3. capped hinge / saturation score
  4. 二元阈值（仅作为机制诊断）
```

每个概念至少登记：

- 经济机制与预期方向；
- 原始字段、单位、时间戳和 point-in-time 可用性；
- 数据缺失、删失和异常值语义；
- 允许使用的形态族；
- 主 horizon、主资产池、主标签；
- 与现有因子的相关性和预期增量；
- 已消耗的全部试验，不只登记成功项；
- 当前状态：`IDEA / SCREENED / CHALLENGER / CONFIRMATORY / FORWARD / NO_GO`；
- 重新开启 NO_GO 所需的新证据。

这里尤其要继承你们现有 Graveyard：已经证伪的方向不能换个 z-score 或阈值就重新包装。

### 2. 数学变换不要无限枚举，使用标准形态词典

单机版建议每个概念默认最多四类：

| 形态 | 适用情况 | AlphaHive 用途 |
|---|---|---|
| Robust rank/percentile | 跨币尺度不同、重尾 | 默认预筛形态 |
| log/符号 log + robust z | 比率、倍数、长尾变量 | 保留相对强度 |
| capped hinge/单调 spline | 阈值后饱和、边际递减 | 连续调制首选 |
| binary/quantile gate | 有明确结构阈值或风险否决 | 诊断或硬门控 |

不建议自动生成 `原值 × z × rank × 8个阈值 × 多窗口`。合理做法是先根据变量语义确定允许的形态：

- 正值比率：优先 `log(x)`；
- 有正负方向的冲击：signed-log 或 robust z；
- 跨币不可比：时间序列 percentile 或同一时点横截面 rank；
- 有交易所上下限/删失：先处理测量语义，不能靠 winsorize 掩盖；
- 理论上只允许单调关系：用单调 spline，不搜索 U 型。

机器学习资产定价研究常把特征按期横截面排序并映射到固定区间，以降低尺度和离群问题；同时也发现非线性及交互可以贡献预测力。[Gu、Kelly、Xiu，NBER](https://www.nber.org/papers/w25398)

### 3. AlphaHive 的 IC/IR 预筛要改成“条件事件 IC”

你们不是普通每日横截面选股，样本单位应是独立的 wash_cvd 事件，而不是每根 bar。

建议预筛指标：

1. `conditional Spearman IC`：因子分数与事件后净收益的秩相关；
2. 分位响应曲线：Q1–Q5 的收益、命中率、MAE/MFE 是否大体单调；
3. 增量 uplift：高分组相对全部 wash_cvd 事件，而不是相对全市场；
4. 覆盖率：因子是否只覆盖一小撮“幸运事件”；
5. regime/资产/年份稳定性；
6. 成本后结果与容量代理；
7. 邻近参数稳定性。

若每个时间桶事件太少，不要硬算每日 IC/IR。可使用：

- pooled Spearman；
- 按“事件簇/日期/资产”cluster bootstrap；
- 以月份或 regime 为 block 计算 IC；
- overlapping events 合并为 episode，或 bootstrap 时绑定在同一簇。

四个 regime 只能算四个稳定性区块，不能把 `IR = mean(IC)/std(IC)` 当高精度统计量。

### 4. 正交化只回答“是否有增量”

推荐流程：

1. 在训练折内，将候选因子对 wash_cvd 原始强度、已保留调制因子及必要市场状态做 ridge residualization；
2. 用残差预测后续收益；
3. 报告 raw 效果和 residual 效果，但把 residual 结果作为“增量性”的主结论；
4. 所有残差化参数只在训练折拟合，禁止全样本拟合后再切 OOS；
5. 高相关因子先按机制族聚类，每族只留一个代表或等权合成。

不建议小样本事件系统直接上 PCA：它可能统计正交，却破坏机制可解释性，而且不同样本期载荷漂移。

### 5. 组合权重：先简单收缩，再考虑复杂模型

AlphaHive 可采用两级组合：

- 机制族内：标准化后等权或平均 rank，避免同一数据源的多个变体重复投票；
- 机制族间：非负 ridge，最多放 2–4 个真正有增量的族。

模型目标应是事件后的净收益、下行风险或成功概率，不是直接最大化历史 Sharpe。组合得分在你们体系里只能用于研究排序/分层，不能自动转成杠杆、仓位或执行许可。

Two Sigma 公开描述的“独立预测 → consensus view → 风险与成本约束组合”可以借鉴其结构，但不应假装知道其内部具体权重方法。[Two Sigma 官方说明](https://www.twosigma.com/about-us/)

### 6. 衰减监控用“事件 vintage”，不要只用滚动日历

每个正式因子保存当时冻结的预测分数，之后按事件发生顺序监控：

- 最近 30/50 个独立事件的 IC/uplift；
- 累计 forward uplift 及置信区间；
- 分数分布漂移、覆盖率漂移；
- 与其他因子的相关性漂移；
- 预期效果与实际效果之差；
- 数据缺失、单位、provider 变化。

建议告警而非自动停用：

- 连续两个事件窗口方向为负；
- 累计下置信界跌破零；
- 分数分布 PSI 明显恶化；
- 收益仍在但完全被成本侵蚀；
- 增量消失、只剩与主 edge 的共线暴露。

任何实际阈值、trigger 或 Paper 联动变化，仍按你们现有 T3/Owner 闸执行。

## 问题 2：为什么“动不动测完没得测”？

### 判断：不是预算太严，而是漏掉了研究漏斗的中间层

你们当前大概是：

```text
想法 → 选一个门槛 → 正式事件回测 → GO/NO_GO
```

这会同时产生三个问题：

1. wash_cvd 已经是稀疏条件样本，再加二元门控，样本量迅速缩水；
2. 一个连续变量被压成一个阈值后，大部分信息被丢掉；
3. 每个粗糙想法都直接消耗正式预算，没有低成本淘汰层。

所以“5–8 个后枯竭”是可以预期的。严格预算仍然是正确的；需要调整的是预算使用方式。

### 建议改成三级漏斗

#### A. Sandbox：不产生正式结论

在已明确标记为 development 的历史数据上，可以低成本运行较多候选：

- 10–20 个概念；
- 每个最多 3–4 个标准形态；
- 多 horizon 仅看响应曲线；
- 只输出 IC、单调性、覆盖率、稳定性和相关性；
- 不叫 OOS、不宣布 GO。

这一层允许快速失败，但所有搜索都进台账。

#### B. Challenger：冻结一个“因子族规格”

进入 Challenger 的条件可设为：

- 至少两个时间区块方向一致；
- 分位响应基本单调或有可解释饱和；
- 不依赖一个资产、一个月份或少数离群事件；
- 相对已保留调制因子仍有增量；
- 邻近窗口/阈值没有断崖式翻转。

在这一层通过 inner walk-forward 选择唯一形态和超参数。

#### C. Confirmatory：消耗季度正式预算

季度“1 主 + 2 次”只检验三个已经冻结的因子族：

- 一个主标签、一个主 horizon；
- 唯一变换；
- 唯一方向；
- 唯一缺失值规则；
- 唯一组合方式；
- 预先写明 GO/NO_GO 条件。

不能在正式窗口里从 16 个形态挑最好的，再说只测试了一个因子。

### 历史数据已经发生“研究层污染”

你们在同一批历史事件上测试了 20+ 概念。即使每次都有独立 OOS，从整个研究组织的视角看，这段历史也已参与模型选择，不再是完全未见数据。

务实处理：

- 现有全部历史数据降级为 development / calibration；
- 旧结论继续保留，但新候选不能再靠同一历史样本完成最终确认；
- 真正确认来自冻结后的 forward shadow，或未来新增的独立时间段；
- 新资产和新 horizon 可以作为复制证据，但不能假装相互独立。

多重检验是金融因子研究的核心问题；文献建议根据实际试验数量控制 false discovery，而不是沿用单次检验的普通门槛。[Harvey、Liu：False and Missed Discoveries](https://people.duke.edu/~charvey/Research/Published_Papers/P143_False_and_missed.pdf)

### 如何扩展研究空间，又不制造 p-hacking

优先顺序：

1. **连续打分替代二元门控**：先看完整响应曲线，确认确有断点才门控。
2. **低阶组合**：只对 shortlist 中 3–5 个因子研究二阶交互，不做全库组合爆炸。
3. **机制复用**：同一概念在 6h/12h/24h、BTC/ETH/山寨、不同 regime 上做复制。
4. **多任务/层级估计**：共享总体斜率，同时允许资产或 regime 有部分偏差，避免每个分组单独估计。
5. **研究新维度而非新指标名**：事件前蓄力、washout 几何、成交吸收、恢复速度、跨市场传导、事件拥挤度、执行可实现性。
6. **保留失败族**：一个概念族充分失败后进入墓地，除非有新数据、新机制或新测量语义，否则不再换皮测试。

多 horizon、多资产增加的是“复制和诊断维度”，不是免费增加的独立样本量。主 horizon 必须预注册，其余只能作为 secondary robustness。

## 问题 3：同一因子的不同数学形态会不会改变结论？

会，而且原因可以分得很清楚。

### 形态可能真正改变结论的情况

- **非线性**：效果只存在于尾部、存在阈值或 U 型；
- **饱和**：从 1.0 到 1.5 有信息，超过 2.0 不再增加；
- **离群值**：原值/z-score 被几个极端点控制，rank 后消失；
- **尺度漂移**：不同币种、regime 的绝对单位不可比较；
- **重尾比率**：log-ratio 比原 ratio 更稳定；
- **删失/上限**：交易所规则造成的边界点不是真正经济极值；
- **缺失不随机**：二元“是否可观测”可能在偷偷代理流动性；
- **交互**：一个变量只有在特定 washout 强度下才有作用。

反过来，严格单调变换不会改变 Spearman IC 或 rank 排序；它只会改变 Pearson IC、线性回归权重和绝对阈值。因此：

- `x`、`log(x)`、`rank(x)` 的 Spearman IC 大幅不同，通常说明样本、缺失处理或 ties 发生了变化；
- rank 有效、原值无效，常提示重尾/离群；
- 只有一个精确阈值有效、邻近阈值都无效，通常是噪音。

Two Sigma 的公开研究也指出，同一风险因子的定义和构造可能产生经济上显著的差异，不能简单选择历史收益最高的版本。[Risk Factors Are Not Generic](https://www.twosigma.com/wp-content/uploads/Thematic_Research_Risk_Premia_4_1.pdf)

### 机构如何处理“形态枚举 × 多重检验”

正确的检验单位是因子族：

```text
H0：这个概念允许的所有预注册形态都没有增量
```

推荐流程：

1. 在 inner training folds 比较允许的形态；
2. 选择一个形态并冻结；
3. outer fold/forward 只评估这个被选中的完整流程；
4. 统计上使用 family-level max-T permutation、Westfall–Young，或至少对族内搜索做 Holm/FDR 调整；
5. 台账记录实际试过的全部形态和阈值；
6. 不把高度相关的 16 个变体粗暴当成 16 个完全独立检验，但也绝不能当成 1 个检验。

如果只追求单机可落地，最实用的是：按日期/事件簇做 block permutation，每次重新执行“形态选择”，记录该因子族最佳统计量的零分布。这样校正的是完整研究流程，而不是某一个幸运形态。

### 结合你们已有结果

**“单特征极值 16 形态全 NO_GO”**

这是比较强的概念族负面证据。不要测试第 17 个形态，除非出现：

- 新数据质量/测量语义；
- 新的经济机制；
- 新的独立 forward 样本；
- 原 16 个形态共同存在明确实现错误。

否则应把该概念族关闭，而不是继续调参。

**“放量 ratio > 1.5 有效，但 > 2.0 边际递减”**

这正是饱和关系，不适合继续搜索更高二元阈值。建议冻结一个研究候选：

```text
score = clip((log(volume_ratio) - log(L)) /
             (log(U) - log(L)), 0, 1)
```

其中 `L/U` 在 development 阶段一次性确定；或者直接用 `[1.0, 2.0]` 区间的单调 capped hinge。检验重点是：

- 1.0→1.5 是否持续增强；
- 1.5→2.0 是否趋平；
- >2.0 是否只是样本更少，而非收益真正反转。

这比比较 `>1.5 / >1.75 / >2.0 / >2.5` 更省预算，也更贴近经济机制。若要改现有正式阈值或 trigger，仍属于你们的 Owner 决策范围；这里仅是研究规格建议。

**“OI 四象限，141 个事件，无增量”**

141 个事件切成四格后，每格有效样本很可能太少。四象限失败不能证明所有连续关系都不存在，但它已经污染了该历史样本。

可做一次且只做探索性的替代诊断：

- OI change 和 price change 分别 robust-rank；
- 用二维平滑面或带收缩的加性模型；
- 检查响应是否连续、是否仅由一个角落驱动。

如果没有稳定梯度，就关闭整个 OI 状态调制族。即便发现曲面，也只能登记为 forward challenger，不能回头把同一批 141 个事件包装成新确认结果。

## 对 AlphaHive 最具体的改造

建议从下一季度开始执行五条：

1. 正式预算维持“1 主 + 2 次”，但计量单位改为“因子概念族”。
2. 增设 `SANDBOX` 层：每个概念最多 rank、语义变换、capped nonlinear、binary 四种标准形态。
3. 默认连续分数；只有风险否决或存在稳定断点时才升级为门控。
4. 将所有已反复使用的历史事件视为 development；新的确认依赖冻结后的 forward shadow。
5. 下一批优先研究“放量饱和分数”和“本地—全球冲击候选”的增量及组合，不再复活 16 形态全败、OI 四象限无增量或 Graveyard 中的方向。

一句话概括：你们缺的不是更多指标，而是“廉价探索 → 因子族选择 → 单一冻结规格 → 真正前向确认”的中间管线。严格预算应保留，但不要让每一个粗糙阈值都直接烧掉正式检验额度。
